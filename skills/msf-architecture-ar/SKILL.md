# msf-architecture-ar

## النطاق

استخدمها لتصميم حدود النظام أو الوحدات داخل تطبيق واحد أو التكاملات أو معالجة الدين التقني وقابلية التوسع وإعادة الهيكلة ومراجعة الكود. اختر تعقيدًا يناسب النظام.

## المدخلات

حالات الاستخدام، ورسم التبعيات، ومالكو البيانات، وتقديرات الحمل، وقيود الأعطال.

## المتطلبات

افحص وحدات النشر والعقود العامة والتخزين ومقاييس التشغيل المتاحة.

## خطوات العمل

1. حدّد جهة الكتابة لكل بيانات وحدود الثقة والقواعد التي يجب أن تظل صحيحة. ابدأ بأبسط تصميم متماسك. قارن API مباشرة أو تطبيقًا أحاديًا معياريًا بطبقات إضافية عندما تبررها القواعد أو التكامل أو قابلية الاستبدال. طبّق SOLID حيث يخفّض الترابط فعليًا.
2. قرّر إصدار العقود والمخطط وحدود المعاملات وتحويل الأخطاء ومعرّف التتبع وإعادة محاولات الوظائف ومنع التكرار. حدّد المهلات وسلوك الحمل الزائد والتراجع. أعد الهيكلة على دفعات يمكن رصدها خلف واجهات مستقرة وراجع المستدعين والبيانات القديمة.

## السلامة

تجنّب كسر العملاء وترحيلًا غير قابل للعكس وتوسيع الصلاحيات دون تفويض. اربط ادعاءات السرعة والتوسع بقياسات.

## المخرجات

خرائط السياق والتبعيات، وعقود API والبيانات، وADR، ومصفوفة الأعطال، وخطة ترحيل، ونتائج مراجعة.

## التحقق

تتبّع حالات الاستخدام والفشل عبر الحدود. اختبر التوافق مع العملاء وقاعدة مجال واحدة على الأقل وسجّل افتراضات الأداء.

## معالجة التعثر

إذا غابت قياسات الأساس فقِس قبل التحسين أو صِف الخطر وتجربة قابلة للعكس.
