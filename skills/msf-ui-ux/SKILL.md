# msf-ui-ux

## Scope

Use to design or critique enterprise UI, dashboards, forms, tables, design systems, RTL/LTR and themes. Apply to user-facing flows.

## Inputs

Product identity, audience, primary tasks, screenshots or implementation, language and target devices.

## Prerequisites

Read existing tokens and components. Use the real UI or a prototype with synthetic data and licensed references.

## Workflow

1. Map the main task and navigation. Compare reference patterns against the product identity, record decisions, and define semantic color, type, spacing, component and state tokens for both themes. Use icons from a licensed SVG set or original vectors.
2. Build and inspect one representative flow. Use CSS logical properties, lang and dir, mixed-direction isolation and readable Arabic type. Add required and optional labels, actionable inline errors, focus recovery, keyboard-operable searchable selectors and trees where needed. Give tables appropriate sort, search, filter, pagination and empty/loading/error behavior.

## Safety

Use only licensed assets. Protect screen captures and user data. Apply the product design system and use Impeccable Critique or the bundled critique rubric for evidence-led review.

## Outputs

Tokens, responsive screen or prototype, annotated critique with severity, acceptance checks and visual baselines.

## Validation

Test keyboard order, focus, contrast, narrow widths, long Arabic, theme/locale pairs, reduced motion and visible feedback. Capture comparable screenshots where tools allow.

## Failure handling

If a critique tool or font is absent, use the bundled rubric and local fallback fonts; mark missing browser evidence BLOCKED.
