# Field procedure — design for the actual product

1. Identify the product name, actual purpose, users, workflow, current visuals and immutable constraints. Treat a name as a clue, not proof of sector or colors.
2. Read [design-direction.md](design-direction.md) before applying the design review; distinguish existing product identity from a new brand exploration.
3. When reviewing an existing UI, keep the task, sections and controls intact unless the user has authorized structural change. When creating a new UI, explore visually distinct directions if they meaningfully improve the decision. Avoid adopting a universal MSF palette, card layout or navigation.
4. Review the path from user entry to feedback. Record each reference, what it solves and how it fits this particular product.
5. Use [Impeccable](https://github.com/pbakaus/impeccable), [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill), [Anthropic Frontend Design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) and [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines) as distinct, optional sources, not design mandates.
6. Critique in order: task blockers, accessibility, information hierarchy, localization, responsive behavior, visual coherence and polish. For every issue record viewport, locale, theme, reproduction, impact and correction.
7. Evaluate mobile touch and desktop keyboard where relevant. Check licenses for any selected font or icon set; use no emoji as product UI icons. Do not invent brand logos or user evidence.
