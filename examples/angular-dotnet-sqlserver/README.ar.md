# رَفّ: سجل المخزون

[English](README.md) · [مسار المهارات وأدلة التحقق](WORKFLOW.md)

رَفّ مثال تدريبي ببيانات اصطناعية لفريق المستودع. يتكوّن من واجهة Angular ثنائية اللغة، وواجهة ASP.NET Core، وقاعدة SQL Server. يبدأ بالعربية واتجاه RTL، ويتيح إضافة صنف والبحث عنه واختيار فئته وتعديل كميته وأرشفته واستعادته. يبقى رمز الصنف محفوظاً عند الأرشفة، ويرفض الخادم الحفظ إذا تغيّرت نسخة الصنف منذ فتحه.

## تشغيل محلي

1. جهّز مثيل SQL Server محلياً مخصصاً للتجربة، وثبّت `sqlcmd` و.NET 10 SDK وNode 22.12+ ضمن سلسلة 22 أو Node 24. نفّذ `sqlcmd -S localhost,1433 -U YOUR_SETUP_LOGIN -C -b -i sql/001-inventory.sql` بحساب التهيئة. خصّص حساب قاعدة بيانات آخر للتطبيق بالصلاحيات الواردة في نهاية ملف SQL.
2. اضبط `ConnectionStrings__Inventory`، و`ASPNETCORE_ENVIRONMENT=Development`، وأنشئ مفتاحين محليين مختلفين للقارئ والمحرر في `Inventory__ReaderKey` و`Inventory__EditorKey`. راجع [الأوامر الكاملة](README.md#run-locally) ثم شغّل `dotnet run --project api --no-launch-profile --urls http://127.0.0.1:5080`.
3. من مجلد `web`، نفّذ `npm ci` ثم `npm start` وافتح `http://127.0.0.1:4200`. أدخل مفتاح المحرر للتعديل أو مفتاح القارئ للاستعراض.
4. للتحقق من الخادم، نفّذ `node tests/smoke.mjs` باستخدام المفتاحين نفسيهما في بيئة الطرفية. ينشئ الاختبار صنفاً اصطناعياً جديداً ويتركه في الأرشيف.

جرّب البحث عن `WT-031` أو «مفتاح عزم»، ثم تصفية الأصناف بالفئة باستخدام اسمها أو رمزها. أضف صنفاً جديداً، وعدّله، وأرشفه، ثم استعده من قائمة الأرشيف. للتحقق من التعارض، افتح الصنف في تبويبين واحفظ تعديلاً في الأول ثم حاول الحفظ في الثاني.

مفاتيح العرض تمثّل دورين محليين مشتركين ولا تعرّف هوية الموظف. استخدام النظام مع مخزون حقيقي يتطلب هوية فردية وسجل تدقيق ومراجعة لصلاحيات الوصول وخطة تشغيل وترحيل مناسبة.
